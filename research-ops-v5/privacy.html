Research Ops V5

Privacy Policy

Effective date: November 10, 2026

Research Ops V5 is a personal-use PhD application assistant operated by Sayem Chowdhury. It is not offered to the public. This policy explains how its read-only Google integration handles the account owner's information.

Google data accessed

When the owner authorizes the integration, it uses read-only Google APIs for Gmail, Google Calendar, and Google Sheets. It may also use a separate, explicitly authorized read-only grant to inspect Apps Script project source during a manual safety audit.

  • Gmail: message and thread identifiers, headers, timestamps, labels, and short snippets may be processed to distinguish academic correspondence from automated or unrelated mail. For a likely interview invitation, the system may temporarily inspect text-only message content when its MIME structure confirms there are no attachments. It does not download attachments.
  • Calendar: event identifiers, titles, dates, times, and timezone information may be processed to identify interviews and schedule changes.
  • Sheets: selected application, contact, status, and deadline fields may be read to match events to the owner's academic records.
  • Apps Script source: source code may be read under a separate, explicitly authorized manual audit grant. Owner-approved source editing, when needed, is a separate local maintenance operation and is not used by the scheduled Workspace monitor.

How data is used

Google data is used only to reconcile correspondence and events with the owner's PhD application records, deduplicate actions, calculate urgency, and prepare private operational summaries. Email text is transient classification input. Saved daily and weekly briefings omit raw subject lines, snippets, message bodies, and document content. Persisted runtime state is minimized to the event and action identifiers, categories, dates, deadlines, source references, verification status, and derived preparation items needed for deduplication, recovery, and review.

The current read-only workflow classifies Google data using deterministic project rules. Optional Telegram alerts require separate owner approval and configuration of a specific private recipient.

Optional Telegram alerts

When the owner activates alerts, the system sends a short event category, a generic required action, and an opaque event reference to the owner's configured private Telegram chat. These categories may reveal that an academic reply, interview, document request, decision, or urgent deadline requires attention. An approved alert path may include a verified Gmail thread link so the owner can open the original evidence. The link can reveal a thread identifier and requires the owner's Google account access to read the message.

Alert content is limited to this summary and any verified source link. Google credentials, email bodies and subject lines, CV contents, attachments, application files, and meeting links are excluded from push messages. Telegram processes the transmitted alert and recipient chat identifier under its Privacy Policy. The bot token and recipient configuration are kept in protected runtime secrets. The system stores minimized delivery attempts and outcomes with its action state for deduplication and recovery.

Where data is processed and retained

Processing can occur on the owner's computer or on GitHub-hosted Actions runners in the owner's private repository. The workflow may retain minimized checkpoints, deduplication state, action summaries, and operational diagnostics in private GitHub Actions artifacts for up to 30 days. These records can include academic event categories, dates, and the minimum evidence needed to resume processing; they do not include full email bodies or attachments. Repository access is controlled by GitHub permissions.

OAuth credentials are kept outside the source repository, either in the owner's local credential storage or in GitHub Actions encrypted secrets. A runner may use a temporary credential file during a run and removes that file afterward. The owner is responsible for the security of their computer and repository access.

Sharing

Google data is used for the owner's academic workflow. Google services and the owner's private GitHub repository and hosted workflow process the data and retain minimized checkpoints. If separately activated, Telegram also receives the limited alert information described above. Repository collaborators authorized by the owner may be able to view retained artifacts. This personal tool has no public sign-up or multi-user workflow.

Choices and deletion

The owner can stop future access by revoking the application's Google account access. The owner can delete local credential files, GitHub Actions artifacts, and repository secrets through the corresponding account settings. Existing data held by Google or GitHub remains subject to those providers' retention and deletion controls.

The owner can stop future Telegram alerts by disabling the delivery gate or removing the bot credentials. Existing messages can be deleted through Telegram. Telegram's own retention and deletion rules apply to information it has already received.
